# Как заниматься

Эта папка — твои учебные заметки: `00-start.md`, `0.3.md` и так далее. Один файл — одно задание. Файл `.md` — обычный текст с простой разметкой; его читает GitHub и любой редактор. Создавать `README.md` в каждой папке не нужно.

Эта страница объясняет, как проходит занятие. Остальное в репозитории — служебные файлы для наставника, читать их заранее не нужно.

## Как проходит занятие

1. **Обнови репозиторий.** В терминале, в папке репозитория на ветке `main`: `git pull`.
2. **Открой Codex** в папке репозитория и напиши фразу из таблицы ниже. Наставник сам прочитает план и прогресс и скажет, где вы остановились.
3. **Занимайся с наставником.** Начало — короткий вопрос на повторение. Дальше новая идея, твоя попытка и подсказки по одной. Код пишешь ты; наставник задаёт вопросы и подсказывает, но готового решения не даёт. Перед запуском записывай, что ожидаешь увидеть.
4. **Сдай работу.** Новая ветка → коммит → `git push` → Pull Request, как в задании 0.1. Название ветки, например: `learning/1.1-available-sessions`.
5. **Защита.** Задание принято не когда код работает, а когда ты объяснила его и сама изменила условие. Для этого попроси защиту (таблица ниже).

## Что говорить Codex

| Что нужно | Что написать |
|---|---|
| Начать занятие | «Начинаем занятие, задание 1.1» |
| Проверить решение | «Проверь задание 1.1» |
| Разобрать мои изменения | «Сделай ревью моих изменений» |
| Защитить задание | «Защита задания 1.1». Для независимой проверки открой **новый чат** и дай ему только файл `.ai/skills/fullstack-mentor/workflows/examiner.md` |

Если Codex не понял, скажи полностью: «Выполни `.ai/skills/fullstack-mentor/workflows/lesson.md` для задания 1.1» (или `check.md`, `review.md`, `defend.md`).

## Какие команды запускать самой

| Зачем | Команда |
|---|---|
| Взять свежую версию | `git pull` |
| Запустить своё решение | `node exercises/solutions/01-javascript/1.1.mjs` (путь к своему файлу) |
| Запустить **свои** проверки | команда из README твоего решения, её записываешь ты |
| Показать, что изменилось | `git status`, `git diff` |
| Сдать | `git switch -c learning/<номер>-<тема>`, `git add`, `git commit`, `git push`, затем PR на GitHub |

Больше ничего запускать не нужно. `scripts/progress.mjs` и файлы в `checks/` — инструменты наставника и CI.

## Правила, чтобы курс работал

- **Свои проверки пишешь ты.** В папках `checks/` лежат проверки наставника, их не копируй и заранее не читай: они подсказали бы ответ. `hints.md` открывает наставник, по одной подсказке.
- **Зелёная проверка — это ещё не «принято».** Она показывает, что код ведёт себя правильно. Принятым задание становится после защиты.
- **Прогресс ведёт наставник.** Файл `progress/README.md` ты не правишь, его обновляют по итогам занятия.
- **В PR отметь помощь ИИ:** что сделал наставник, что ты проверила сама, что осталось непонятным.

## Если красный CI

Красный крестик у PR не значит, что ты что-то сломала. Открой PR → вкладка **Checks** (или ссылка Details рядом с крестиком) → красный шаг → строки с ошибкой. Скопируй их наставнику со словами: «ожидала / получила». Жёлтое предупреждение про прогресс красным не считается: наставник обновит строку на занятии.
