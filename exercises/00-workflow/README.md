# Этап 0. Среда и первая совместная работа

[Каталог и правила сдачи](../README.md) · [Далее: JavaScript](../01-javascript/README.md)

**До старта:** GitHub-аккаунт ученика и согласованный способ участия: приглашение или fork. Наставник помогает установить Git, редактор и поддерживаемую Node.js LTS. На этом этапе понимание кода важнее самостоятельной установки всех инструментов.

## 0.1 — Первый учебный PR

**Задача.** Создать `learning/00-start.md`: организация подтверждённых 8–10 часов в неделю (чтение, код, разборы, исправления и проверки входят в них), цель на первые две недели, три вопроса и бытовая задача для автоматизации. Прочитать README, найти одно неясное место и предложить уточнение в своей заметке. Личные и рабочие сведения не нужны.

После первых двух недель обсудить фактическое время, законченный результат, помощь и самостоятельное объяснение/изменение. Если ещё на этапе 0, калибровать по нему, не считать 1.1 принятым по дате.

**Сдать:** отдельную ветку, коммит и PR. Участие через fork допустимо.

**Приёмка:**
- В diff только намеренные изменения; ученик объясняет каждую строку.
- Получено одно замечание наставника, правка добавлена в тот же PR.
- Ученик различает локальный файл, коммит, push, PR и merge.

**Изменение на защите:** исправить формулировку цели и показать, что добавится в следующий коммит, до его создания.

## 0.2 — Запустить и объяснить ошибку

**Задача.** В `exercises/solutions/00-workflow/` создать `hello.mjs`, который выводит строку `Готов к первому заданию`. Зафиксировать фактическую версию Node.js и команду запуска в README решения. Затем скопировать пример в `debug.mjs`:

```js
const freePlaces = 2;
console.log(freePlace + 1);
```

Предсказать результат, запустить, найти файл и строку по сообщению, записать гипотезу и исправить ошибку. Это намеренно неверный учебный код.

**Сдать:** два файла и заметку «ожидал / получил / причина / проверка» без полного лога машины.

**Приёмка:**
- Оба файла запускаются указанными командами; второй выводит `3`.
- Записано исходное сообщение ошибки и объяснено, почему выполнение остановилось.
- В консоли браузера вычислено такое же выражение; ученик знает, что браузер и Node — разные среды.

**Изменение на защите:** изменить исходное число так, чтобы получить `6`, и объяснить результат до запуска.

При разборе показать отдельно редактор (файл), терминал (команда и процесс), Node.js (исполнение) и консоль браузера (другая среда). По сообщению найти файл/строку, проверить гипотезу повторным запуском и остановить собственный процесс. Самостоятельная установка всех инструментов не становится экзаменом.

## 0.3 — Восстановление правки и конфликт

**Задача.** В отдельном локальном тренировочном репозитории создать `notes.md` с одной строкой `Цель: первый PR`. С общего коммита создать две ветки и по-разному изменить эту же строку. Объединить ветки, прочитать конфликт и сохранить согласованный текст. Не тренироваться на основной ветке общего репозитория.

После этого сделать в тренировочном файле ненужную незакоммиченную правку, посмотреть diff и вернуть **только её** к сохранённому состоянию. Наставник сначала объясняет область действия выбранной команды.

**Сдать:** `learning/0.3.md` с короткой схемой коммитов, причиной конфликта и способом восстановления. Вложенный `.git` в общий репозиторий не добавлять.

**Приёмка:**
- Сохранено осмысленное итоговое предложение, маркеров конфликта нет.
- Ученик объясняет, какая версия файла использована и почему.
- Восстановление незакоммиченной правки не удалило полезный коммит.
- Тренировочные процессы остановлены; состояние общего репозитория не повреждено.

**Изменение на защите:** получить бесконфликтное объединение правок в двух разных файлах и объяснить отличие.
