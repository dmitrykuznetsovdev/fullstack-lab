# Этап 1. Типичные ошибки и подсказки по ступеням

[Условия этапа](README.md) · [Скилл наставника](../../.ai/skills/fullstack-mentor/SKILL.md)

Файл для наставника и ученицы. Подсказки открывать **по одной ступени**, начиная с первой. Готового кода решения здесь нет и не будет: ступень 5 из скилла (короткий пример на другом сюжете) наставник даёт сам, если ступени 1–4 не помогли.

## 1.1 — Найти свободные занятия

**Аналогия.** Список занятий — стопка карточек. Функция не переписывает карточки и не перекладывает стопку, а откладывает подходящие в новую стопку в том же порядке.

**Типичные ошибки**
- `>` вместо `>=`: занятие ровно с `minPlaces` местами теряется.
- Проверка `minPlaces <= 0` пропускает `1.5`, `NaN` и `'2'`: `NaN <= 0` даёт `false`, а `'2' <= 0` сравнивает число со строкой после неявного преобразования.
- `typeof x === 'number'` считается проверкой целого, хотя `NaN` и `1.5` тоже числа.
- Выбрасывается `Error` или возвращается `[]` вместо `RangeError`.
- Сортировка или `push` в исходный массив меняют вход.

**Ступени**
1. Что должно получиться при `minPlaces = 3` для примера из условия? Какие занятия должны остаться?
2. Граница здесь — сравнение `freePlaces` с `minPlaces` и проверка самого `minPlaces` до работы со списком.
3. Прочитать про `Number.isInteger` и `Array.prototype.filter` на MDN. Предсказать `Number.isInteger(NaN)`, `Number.isInteger('2')`, `Number.isInteger(1.5)`.
4. План: сначала проверить `minPlaces` и выбросить `RangeError`; затем пройти по списку, оставляя подходящие; вернуть новый массив.

## 1.2 — Разобраться в чужой функции

**Аналогия.** Попросили выписать из журнала подходящие строки, а исполнитель сначала переставил страницы в самом журнале. Выписка может оказаться верной, но журнал уже испорчен.

**Типичные ошибки**
- Не заметить, что `sort` меняет исходный массив, а не только результат.
- Исправить порядок копией `[...sessions].sort(...)`, хотя сортировки пользователь не просил вовсе.
- Найти только одну из двух ошибок: границу `>` или изменение порядка.
- Проверять только результат и не проверять вход после вызова.

**Ступени**
1. Каким будет массив `sessions` после вызова? Выведи его до и после.
2. Две независимые границы: сравнение мест и метод, который работает «на месте».
3. Прочитать раздел MDN о `Array.prototype.sort`: что он возвращает и что делает с исходным массивом.
4. План: воспроизвести оба нарушения отдельными проверками до правки; убрать причину каждого; повторить проверки.

## 1.3 — Посчитать записи

**Аналогия.** Подсчёт голосов: на каждого кандидата заводим строку и ставим палочку за каждый бюллетень, не перечитывая всю пачку заново.

**Типичные ошибки**
- `counts[id] = (counts[id] || 0) + 1` при `id = 'constructor'`: у обычного объекта уже есть унаследованное поле `constructor`.
- Возвращается `Map`, хотя условие просит объект.
- Отменённые записи создают ключ со значением `0`.
- Для каждой записи заново фильтруется весь массив, и число чтений растёт как квадрат длины.

**Ступени**
1. Что вернётся для одной активной записи на `constructor`? Предскажи, затем проверь в консоли `({}).constructor`.
2. Граница — где хранится промежуточный счёт и как превращается в итоговый объект.
3. Прочитать про `Map` и `Object.fromEntries` либо `Object.create(null)` на MDN. Сравнить, что в них есть «по умолчанию».
4. План: один проход по записям; пропускать отменённые; увеличивать счётчик по `sessionId` в хранилище без унаследованных ключей; в конце вернуть объект.
