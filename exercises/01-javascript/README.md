Исходные данные для первых двух заданий:

```js
const sessions = [
  { id: 'a', title: 'Рисование', freePlaces: 0 },
  { id: 'b', title: 'Шахматы', freePlaces: 2 },
```

## 1.1 — Найти свободные занятия

**Подготовка:** на другом небольшом сюжете разобрать значения, `const`/`let`, условие/сравнение, параметры и результат функции, массив/объект, цикл, преобразование строки и числовую границу. Предсказать результат, запустить, объяснить и самостоятельно изменить одно условие. Неподтверждённый механизм закрепить меньшей пробой до основной функции; синтаксис можно смотреть. [Чтение под подготовку](../../docs/reading.md#подготовка-механизма-и-малая-проверка).

**Задача.** Реализовать `getAvailableSessions(sessions, minPlaces)`: вернуть занятия с `freePlaces >= minPlaces`, сохранив исходный порядок и не изменив вход. `minPlaces` — целое число больше нуля; иначе `RangeError`. На этом шаге массив и поля занятий считаем валидными.

**Сдать:** функцию и проверки. Для примера выше при `minPlaces = 2` ожидаются id `b, c`.

**Приёмка:**
- Проверены пустой массив, отсутствие результатов, точная граница и несколько результатов.
- `0`, `-1`, `1.5`, `NaN` и строка `'2'` отклоняются; вход не изменён.
- Ученик объясняет параметры, результат и разницу между `>` и `>=`.

**Изменение на защите:** добавить необязательный `excludeId`, исключающий одно занятие; сохранить прежнее поведение без этого аргумента.

## 1.2 — Разобраться в чужой функции

**Задача.** По контракту 1.1 функция ниже должна вернуть id `b, c` и не менять вход. Сначала предсказать фактический результат и состояние массива, затем воспроизвести оба нарушения и исправить причину. `minPlaces` здесь считаем уже проверенным.

```js
function selectSessions(sessions, minPlaces) {
  return sessions
    .sort((a, b) => b.freePlaces - a.freePlaces)
    .filter(session => session.freePlaces > minPlaces);
}
```

**Сдать:** исходное воспроизведение в описании PR, исправленную функцию и регрессионные проверки.

**Приёмка:**
- Отдельно обнаружены пропуск точной границы и изменение порядка исходного массива.
- Есть проверки состава результата, его порядка и неизменности входа; они выявляют исходные нарушения.
- Исправление сохраняет контракт, не вводя сортировку, которой пользователь не просил.

**Изменение на защите:** объяснить разницу между новым массивом и глубоким копированием объектов; показать на отдельном маленьком примере.

## 1.3 — Посчитать записи

**Задача.** Реализовать `countActiveBookings(bookings)`. Валидная запись имеет `id`, `sessionId` и `status: 'active' | 'cancelled'`. Вернуть объект с числом активных записей по занятиям. Занятия без активных записей не включать; повторяющихся id во входе нет. Для пустого входа вернуть пустой объект.

Пример: `[{id:'1',sessionId:'a',status:'active'}, {id:'2',sessionId:'a',status:'cancelled'}, {id:'3',sessionId:'b',status:'active'}]` → `{a:1,b:1}`. `sessionId` — произвольная строка, в том числе `constructor`; можно использовать `Map` внутри, но результат — объект.

**Сдать:** функцию, проверки и объяснение алгоритма своими словами.

**Приёмка:**
- Проверены пустой вход, только отменённые записи, несколько записей одного занятия и несколько занятий.
- Ключ `constructor` обрабатывается как обычный id, вход не меняется.
- Ученик показывает, сколько раз читается запись при одном проходе и при поиске по всему массиву для каждого элемента. Формальный вывод сложных оценок не нужен.

**Изменение на защите:** возвращать отдельно количество активных и отменённых записей для каждого встреченного занятия; сформулировать новый пример до кода.

**Малые результаты внутри 1.3 перед переходом дальше:**

1. В собственной малой пробе на другом сюжете разделить функцию и вызывающий файл через `export`/`import`. Запустить, объяснить границу модуля, найти ошибку неверного импорта по диагностике и самостоятельно изменить условие. Готовую реализацию основного задания эта проба не заменяет.
2. На локальной асинхронной функции показать ожидание, успешный Promise и отклонение. Предсказать порядок синхронной части и продолжения после `await`, объяснить возврат Promise и границу `try/catch`, затем проверить собственное изменение. Полный порядок всех очередей среды знать не требуется.
3. После понимания локальной команды проверок добавить простой GitHub Actions workflow для JS-проверок на PR: наблюдать падение на временно неверном ожидании и прохождение после восстановления. Удалить неверную пробу из итогового кода, показать команду и лог. Новый механизм автоматизации сначала проверить малым шагом; знакомую настройку можно ограниченно делегировать с ревью и независимой защитой.
