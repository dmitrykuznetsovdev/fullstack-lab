# Глоссарий: термины простыми словами

[План](../README.md) · [Чтение](reading.md) · [Практика](../exercises/README.md) · [Прогресс](../progress/README.md)

Короткие определения с бытовыми аналогиями. Аналогия помогает запомнить идею, но не точна: там, где она ломается, это написано. Подробности — в разделах чтения из [reading.md](reading.md) или по команде `/theory <термин>`. Глоссарий пополняется по мере занятий: новые термины добавляем вместе с наставником. Оригинальные английские слова указаны в скобках: именно их вы увидите в терминале и в документации.

## Git и GitHub

| Термин | Простыми словами | Аналогия и где она ломается |
| --- | --- | --- |
| Git | Программа на компьютере, которая хранит историю версий файлов проекта | История сохранений в игре. Но Git хранит не весь проект целиком каждый раз, а изменения по выбранным вами точкам |
| GitHub | Сайт, где хранятся удалённые копии репозиториев и идёт обсуждение изменений | Облачный диск с обсуждением. Git и GitHub — разные вещи: Git работает и без GitHub |
| Репозиторий (repository, repo) | Папка проекта вместе с историей версий; история лежит в скрытой папке `.git` | Папка с документами и журналом всех правок |
| Локальный и удалённый репозиторий | Локальный — копия на вашем компьютере; удалённый (remote) — копия на сервере, например на GitHub | Рабочий черновик дома и общий экземпляр в офисе |
| `origin` | Стандартное имя удалённого репозитория, откуда вы клонировали проект | Контакт «Офис» в телефонной книге |
| Клонировать (clone) | Скопировать удалённый репозиторий вместе с историей на свой компьютер | Копия папки со всем журналом правок |
| Fork | Своя копия чужого репозитория на GitHub, где можно править без доступа к оригиналу | Ксерокопия книги, в которой вы делаете пометки |
| Коммит (commit) | Сохранённый набор изменений с подписью: что и зачем изменено | Точка сохранения в игре с заметкой. К ней можно вернуться |
| Индекс, область подготовки (index, staging area) | Набор изменений, выбранных для следующего коммита (`git add`) | Корзина перед кассой: вы выбираете, что оплатить сейчас |
| Ветка (branch) | Подвижная метка на коммите; на ней растёт отдельная линия правок | Копия черновика для экспериментов. Но Git не копирует файлы, а двигает метку |
| `main` | Основная ветка, в которую сливают готовые изменения | Чистовик документа |
| `HEAD` | Указатель на ветку и коммит, на которых вы сейчас стоите | Отметка «вы здесь» на карте |
| Push | Отправить свои коммиты в удалённый репозиторий | Загрузить черновик в облако |
| Fetch, pull | Fetch — скачать новые коммиты без изменения ваших файлов; pull — скачать и сразу объединить с вашей веткой | Fetch — посмотреть почту, pull — посмотреть и сразу подшить письма в дело |
| `diff` | Показ различий между двумя версиями: что удалено (`-`), что добавлено (`+`) | Режим рецензирования в текстовом редакторе: красным удалённое, зелёным добавленное |
| Pull Request (PR) | Заявка на GitHub: «влейте мою ветку в `main`»; в ней обсуждают и проверяют изменения | Заявка «посмотрите мои правки перед тем, как вставить их в общий документ» |
| Слияние (merge) | Объединение изменений двух веток в одну | Сведение двух редакций документа в одну |
| Конфликт слияния (merge conflict) | Две ветки изменили одно и то же место по-разному; Git просит выбрать итог и оставляет в файле маркеры `<<<<<<<`, `=======`, `>>>>>>>` | Два редактора переписали один абзац. Git не выбирает за вас, потому что не знает смысла |
| Откат правки (`git restore`) | Вернуть файл к последнему сохранённому состоянию. **Незакоммиченную правку так вернуть нельзя обратно:** сначала смотрите `git diff` | Ластик без корзины. Закоммиченное восстановить можно, а несохранённое нет |
| Рабочее дерево, worktree | Дополнительная рабочая папка того же репозитория, где открыта другая ветка | Ветка — карандашная метка в журнале, worktree — отдельный стол, на котором лежит копия этой версии. Метка не занимает места, стол занимает |
| `.gitignore` | Список файлов и папок, которые Git не должен отслеживать (зависимости, секреты, сборка) | Список «в архив не класть» |

## Файлы и терминал

| Термин | Простыми словами | Аналогия и где она ломается |
| --- | --- | --- |
| Терминал, командная строка (terminal, shell) | Окно, где управляют компьютером текстовыми командами | Разговор с компьютером письменно: одна команда — один приказ. Ошибка в команде выполняется буквально |
| Markdown, файл `.md` | Обычный текстовый файл с простой разметкой (`#` — заголовок, `-` — список, `**текст**` — жирный); GitHub показывает его красиво оформленным | Текст с карандашными пометками «это заголовок». Файл `.md` не нужен в каждой папке; `README.md` по соглашению GitHub показывает как описание папки |
| `README.md` | Файл-визитка проекта или папки: что это и как начать | Титульный лист папки |
| `learning/` | Каталог этого репозитория для заметок ученицы по заданиям (что поняла, где запнулась) | Личный дневник учёбы рядом с проектом |
| `exercises/solutions/` | Каталог для решений ученицы | Тетрадь с выполненными заданиями |

## Запуск кода

| Термин | Простыми словами | Аналогия и где она ломается |
| --- | --- | --- |
| Node.js | Программа, которая запускает JavaScript вне браузера: `node файл.mjs` | Отдельная кухня для того же рецепта. Это другая среда, чем браузер: в ней нет страницы и `document` |
| Консоль браузера (browser console) | Окно в инструментах разработчика, где выполняют JavaScript прямо на странице | Другая среда исполнения, чем Node.js; результат одной строки может отличаться |
| Сообщение об ошибке (error message, stack trace) | Текст с типом ошибки, описанием и строкой в файле, где выполнение остановилось | Квитанция о поломке: читать её надо сверху, находя файл и строку |
| `ReferenceError` | Ошибка: имя не найдено. Часто из-за опечатки в названии переменной | Обращение к человеку, которого нет в списке |
