# Прогресс Fullstack Lab

[План](../README.md) · [Условия заданий](../exercises/README.md) · [Режим наставника](../.ai/skills/fullstack-mentor/SKILL.md)

**Это единственный источник учебного состояния.** Условия находятся в exercises, маршрут — в корневом README. Здесь отмечаем состояния, доказательства, текущую задачу, навыки, затруднения и журнал. Наличие учебной инфраструктуры не означает выполненного занятия.

## Где продолжить

- **Текущая выбранная задача:** [0.1 — Первый учебный PR](../exercises/00-workflow/README.md#01--первый-учебный-pr). Её состояние находится в таблице этапа 0 ниже.
- **Место остановки:** учебные задания ещё не начаты; решений и результатов занятий нет.
- **Следующий небольшой шаг:** вместе прочитать план, обсудить доступный темп без персональных сведений, затем создать свою учебную заметку по 0.1. Способ участия через приглашение или fork ещё предстоит согласовать.
- **Тема продукта:** не выбрана. Занятия/бронирование используются для упражнений.
- **Для возвращения после перерыва:** прочитать этот блок и последнюю фактическую запись журнала, затем условия текущей задачи и её решение, если оно появилось. Кратко напомнить точку остановки и предложить небольшой шаг/повторение; не предполагать освоение.

## Как отмечать состояние

| Состояние задания | Когда ставить |
| --- | --- |
| Не начато | Нет подтверждённой попытки |
| В работе | Ученица приступила; указать конкретный шаг или артефакт |
| На проверке | Решение представлено, приёмка/защита ещё не завершена |
| Нужна доработка | Есть конкретный незакрытый критерий и следующий шаг |
| Принято | Все критерии проверены, объяснение и изменение на защите состоялись; есть доказательство |

В колонке «Доказательство / следующий шаг» указывать ссылку на PR, файл решения или наблюдение, выполненные проверки и помощь. Для двух режимов предметно отметить: новый или подтверждённый механизм, что реализовал агент, какие требования и проверки сопоставила ученица, что объяснила и изменила сама, какие подсказки понадобились. Перед делегированием подтверждение относится к конкретному механизму и уровню задачи: объяснение, собственная малая проба/изменение и наблюдаемая проверка. Доля сгенерированного кода не определяет уровень самостоятельности; зелёный CI без понимания не подтверждает освоение. При непонимании вернуться к малой пробе. Отдельного реестра разрешений нет. Не считать «все тесты прошли» доказательством без перечня проверяемого поведения. Если занятие прервано, оставить фактическое состояние и точку продолжения. Этап/эпик завершён, когда все три задания приняты и выполнен критерий перехода из плана; отдельное ручное поле состояния эпика не ведём.

## Подтверждённые темы и затруднения

**Освоенные темы:** пока не оценены; подтверждённых навыков нет. Это отсутствие проверки, а не вывод о способностях ученицы.

После реальной проверки добавлять строку «тема → конкретное действие → уровень самостоятельности → ссылка на доказательство». Уровни: с пошаговой помощью / с подсказками / самостоятельно / переносит навык. Не заполнять весь перечень технологий заранее отметками «освоено».

**Затруднения:** пока не наблюдались. После занятия записывать конкретный вопрос или незакрытый критерий, а также небольшое упражнение для повторения; не приписывать затруднение по отсутствию решения.

## Журнал занятий

Фактических записей пока нет. После каждого реального занятия добавлять короткую запись сюда; подробные заметки ученицы доступны по ссылке. Историю сохранять, блок «Где продолжить» обновлять до актуальной точки остановки. Повторно переписывать состояния всех заданий в записи занятия не нужно.

Шаблон ниже не является состоявшимся занятием:

```text
Дата фактического занятия:
Задание и ограниченная цель:
Что ученица сделала и как это проверено (ссылка):
Что объяснила/изменила сама; какая была помощь:
Что пока не получилось или не проверено:
Где остановились в решении:
Следующий небольшой шаг / что повторить:
```

## Связь с GitHub Issues и PR

Локальные восемь этапов служат эпиками, задания — их небольшими задачами. Создавать Issues по необходимости, например «3.2 — Компоненты, сборка и общий store», с ссылкой на условия и этот файл. В PR указывать номер задания; ссылку на PR/Issue хранить в строке задания как доказательство. Закрытие Issue само по себе не подтверждает освоение.

Ручной учебный статус, текущую задачу и журнал вести только здесь; отдельную копию чек-листа прогресса в Issues/Project/README не поддерживать. Условия в Issue не копировать целиком: источник — exercises. Внешние Issues и эпики в рамках подготовки программы не создавались.
