## Как отмечать состояние

| Состояние задания | Когда ставить |
| --- | --- |
| Не начато | Нет подтверждённой попытки |
| В работе | Ученица приступила; указать конкретный шаг или артефакт |
| На проверке | Решение представлено, приёмка/защита ещё не завершена |
| Нужна доработка | Есть конкретный незакрытый критерий и следующий шаг |
| Принято | Все критерии проверены, объяснение и изменение на защите состоялись; есть доказательство |

В колонке «Доказательство / следующий шаг» указывать ссылку на PR, файл решения или наблюдение, выполненные проверки и помощь. Для двух режимов предметно отметить: новый или подтверждённый механизм, что реализовал агент, какие требования и проверки сопоставила ученица, что объяснила и изменила сама, какие подсказки понадобились. Перед делегированием подтверждение относится к конкретному механизму и уровню задачи: объяснение, собственная малая проба/изменение и наблюдаемая проверка. Доля сгенерированного кода не определяет уровень самостоятельности; зелёный CI без понимания не подтверждает освоение. При непонимании вернуться к малой пробе. Отдельного реестра разрешений нет. Сверка с фактами — `node scripts/progress.mjs --check`, она же выполняется в CI. Валят проверку только ошибки учёта: неизвестное состояние, состояние без доказательства, «Принято» при падающей автопроверке. Решение в репозитории при состоянии «Не начато» — предупреждение: прогресс обновляет наставник на занятии, ученица его не правит. Автопроверка подтверждает только поведение кода; «Принято» ставится после защиты. Не считать «все тесты прошли» доказательством без перечня проверяемого поведения. Если занятие прервано, оставить фактическое состояние и точку продолжения. Этап/эпик завершён, когда все три задания приняты и выполнен критерий перехода из плана; отдельное ручное поле состояния эпика не ведём.
